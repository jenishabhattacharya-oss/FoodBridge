SharePlate — Project Overview

A web platform connecting surplus food with people who need it. November 2026.

1. What the website is

SharePlate moves surplus food from donors to verified NGOs. A donor posts food with photos and a pickup window. A staff-verified NGO reviews the food for safety and accepts it. A volunteer collects it and delivers it. The NGO confirms receipt, closing the loop. If no volunteer is available, the NGO handles the pickup itself. Every step — status, timestamps, photos, recipient details — is recorded.

3. Rules that make it trustworthy

  • Three separate roles — Donor, NGO, Volunteer. Each account is exactly one role, with its own workspace and server-enforced permissions.
  • NGOs are verified — a newly registered NGO can log in but cannot act on any listing until staff approve it in the admin panel.
  • Volunteers see only accepted pickups — and can hold one active pickup at a time.
  • Object-level permission checks — every view verifies the caller actually owns or is assigned to the record.
  • Full audit trail — status changes, timestamps, photos and recipient details are stored on each donation.

5. How the AI food-safety screening works

When a donor submits photos, the system can screen them with the Google Gemini vision API before a human ever sees them:

  1. The photos are sent to the model with a strict prompt: check only visible warning signs (spoilage, mold, pests, damaged packaging). The model must reply in JSON with a decision — approve, reject, or review — plus a confidence score and risk flags.
  2. The reply is parsed, validated and range-checked before any status changes.
  3. Graceful degradation: if there is no API key, the model is unsure, or the API fails, the listing goes to a human review queue instead of being blocked. Reviewers are reminded that a visual check is not a food-safety certification.
